# Vior — Operating Manual

End-to-end guide for the Vior desktop + Android companion: install, pair, use, troubleshoot, rebuild, and navigate the repo (including the `.claude/` agent worktree pool).

---

## 0. Build artifacts

| Component | Default install path | Source |
|---|---|---|
| Desktop app (macOS) | `/Applications/vior-app.app` | local `wails build` |
| Android APK | `~/Downloads/vior-latest.apk` | CI artifact `vior-mobile-Android` (`app-debug.apk`) |

## 1. Repo layout (top-level)

| Path | What it is |
|---|---|
| `desktop/` | Wails app — Go backend + Vite/TS frontend (the macOS window). |
| `desktop/frontend/wailsjs/` | **Auto-generated** TS bindings to Go methods. Committed so the frontend imports them; regenerated by `wails build`. |
| `desktop/build/bin/vior-app.app` | Local Wails build output. Gitignored. |
| `internal/` | Go packages used by both desktop and CLI: `filetransfer`, `input`, `usb`, `protocol`, `stream`, `network`, `trust`, etc. |
| `mobile-cap/` | Capacitor-wrapped Android app. TypeScript sources under `mobile-cap/src/js/`, native shell under `mobile-cap/android/`. |
| `mobile-cap/android/` | Mostly Capacitor-regenerated. CI does `rm -rf android && npx cap add android` per build and restores only the tracked customs (Java sources, `AndroidManifest.xml`, `drawable/`, `mipmap-*`, `values/` overrides). |
| `cli/` | Command-line variant of Vior (no GUI). |
| `docs/` | Project docs (this file, master-plan, audits). |
| `docs/site/` | Marketing / docs site (Lottie animations live in `docs/site/animations/`). |
| `.github/workflows/` | CI build matrix: Desktop (mac/win/linux), CLI (mac/win/linux), Mobile (Android). |
| `.claude/worktrees/` | Agent scratch worktrees — see §11. Gitignored. |

## 2. Launch desktop (macOS)

```bash
open /Applications/vior-app.app
```

First launch may be blocked by Gatekeeper. Unblock via:

- **System Settings → Privacy & Security → "Open Anyway"**, or
- `xattr -dr com.apple.quarantine /Applications/vior-app.app` then relaunch.

---

## 3. Install APK on Android

### Option A — `adb` (USB cable, fastest)

1. Enable *Developer options → USB debugging* on phone.
2. Plug phone into Mac.
3. ```bash
   adb devices                            # confirm phone listed
   adb install -r ~/Downloads/vior-latest.apk
   ```

If reinstall fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE` (signature mismatch):

```bash
adb uninstall com.vior.mobile
adb install ~/Downloads/vior-latest.apk
```

### Option B — sideload (no `adb`)

1. Transfer APK to phone (AirDrop / email / Drive / `scp`).
2. Tap the APK → allow *Install unknown apps* for the file manager → Install.

---

## 4. Pair phone ↔ Mac (Wi-Fi mode)

1. Launch `vior-app` on Mac. Main screen shows the **pair code** (a 4-digit number derived from your Mac's hardware ID; override in Settings).
2. Both devices on the same Wi-Fi subnet.
3. On phone: open Vior → Discovery screen auto-lists the Mac.
4. Tap the Mac entry → enter pair code → connected.

Available tabs once paired:

- **Stream** — mirror Mac display to phone
- **Remote** — trackpad + soft keyboard control of Mac
- **Files** — bi-directional file transfer

---

## 5. USB-AOA mode (cable, no Wi-Fi)

1. Plug phone → Mac via USB.
2. Mac auto-detects via Android Open Accessory. Orb transitions: scanning → verifying → connected.
3. Phone shows "Vior — USB connected".

**Heartbeat:** desktop sends `FramePing` every 5s, tears down on no `FramePong` for 10s. Stale "USB connected" states resolve on their own.

**Limitation:** cable currently carries display only. Remote-tab input (trackpad/keys) still needs Wi-Fi. A one-shot toast on the phone surfaces this the first time you try Remote over USB. The AOA input-frame extension is the known follow-up.

---

## 6. File transfers

| Direction | How |
|---|---|
| Mac → phone | Files tab → **Send** → pick file. Live progress bar fills as bytes flow. |
| Phone → Mac | Files tab → **+** → pick. Mac modal pops with thumbnail + Accept/Reject. |

- LAN ceiling: ~48 MB/s (WS-chunked, 1ms inter-chunk yield).
- Hard cap: `MaxDownloadSize` constant in `internal/filetransfer/filetransfer.go`. Oversize offers auto-reject before disk is opened.
- Filenames sanitized: traversal (`../`), control chars, Windows reserved names, leading dot/dash, and >255-byte names all neutralized.

## 7. Remote tab gestures

| Gesture | Action |
|---|---|
| One-finger drag | Move cursor — sub-linear acceleration (small=precise, fling=fast) |
| Tap | Left click |
| Two-finger tap | Right click |
| Two-finger drag | Scroll |
| Soft keyboard | Sends keys via `darwinKeyCodes` |

**Warp-back guard:** cursor only snaps to main-display centre if it has wandered off *both* the host's main display *and* the captured virtual display.

## 8. Pair code override

Mac app → **Settings → Pair code**:

- **View** current code
- **Override** with any 4-digit value
- **Reset** to deterministic default (machine-id keyed)

Persists across launches.

## 9. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Phone doesn't see Mac in Discovery | Different Wi-Fi subnets, or macOS firewall blocking. Verify listener: `lsof -iTCP -sTCP:LISTEN \| grep vior`. |
| USB orb stuck on "verifying" | Unplug, replug. Heartbeat auto-kills wedged sessions after 10s. |
| `adb install` fails with `UPDATE_INCOMPATIBLE` | Signature mismatch with prior install. `adb uninstall com.vior.mobile` first. |
| Desktop won't open ("damaged"/"unidentified") | Gatekeeper. `xattr -dr com.apple.quarantine /Applications/vior-app.app`. |
| File transfer "stuck at 0%" | Receiver hasn't accepted. Check the destination side for the accept modal. |
| Remote tab input silently no-ops on USB | Expected. Use Wi-Fi for trackpad + keys. |
| Launchpad still shows a deleted Vior app | macOS Launchpad caches. Force re-index: `killall Dock`. Spotlight index lives in build dirs — check `mdfind -name "vior-app"`. |
| Push fails 403 | Multi-account `gh`. `gh auth status` to see active account; `gh auth switch --user subhashraveendran` to switch. |

## 10. Rebuild from source

### Desktop (macOS)

```bash
cd "/Users/subhashraveendran/Documents/Source Codes/Vior/desktop"
wails build
rm -rf /Applications/vior-app.app
cp -R build/bin/vior-app.app /Applications/
```

### Android APK — CI route (preferred, no local Android SDK needed)

```bash
gh run list --workflow Build --limit 1 --branch main         # latest run ID
gh run download <id> --name vior-mobile-Android --dir /tmp/apk
mv /tmp/apk/app-debug.apk ~/Downloads/vior-latest.apk
```

Note artifact name is **`vior-mobile-Android`** (capital A). List artifact names if unsure:

```bash
gh api repos/subhashraveendran/Vior/actions/runs/<id>/artifacts --jq '.artifacts[].name'
```

### Android APK — fully local (needs Android SDK + `npx cap`)

```bash
cd mobile-cap
npm run build
npx cap sync android
cd android && ./gradlew assembleDebug
cp app/build/outputs/apk/debug/app-debug.apk ~/Downloads/vior-latest.apk
```

## 11. The `.claude/` folder and agent worktrees

Vior is developed with Claude Code as the primary IDE. Two things live here:

### What's inside

```
.claude/
└── worktrees/
    ├── agent-a04d1e6693fb5fbd9   → branch fix/remote-tab-input        (locked)
    ├── agent-af328c47658e89e14   → branch fix/verify-files-remote-aoa (locked)
    └── ... (~20 more)
```

Each `agent-<id>/` is a **git worktree** — a checkout of the same repo on a different branch, sharing the same `.git` object database. They are spawned whenever an agent runs with `isolation: 'worktree'` so it can:

- edit code without colliding with your main checkout,
- run builds/tests against an isolated working tree,
- merge back via a normal branch + PR/merge instead of clobbering files.

### Why it's safe to leave alone

- `.claude/` is **gitignored** (`.gitignore:36`) — none of this content ships to GitHub.
- Each worktree is `locked` so `git gc` and `git worktree prune` won't yank them out from under a running agent.
- Branches are real local branches, visible in `git branch`. Useful when you want to inspect what an agent built.

### When you'd want to clean up

`.claude/` is currently ~**1.1 GB** because every agent worktree carries its own `node_modules/`, build artifacts, etc. If disk pressure matters:

```bash
# Inspect: list every worktree and the branch it's on
git worktree list

# Drop one specific worktree (also delete its branch if you don't need it)
git worktree remove --force .claude/worktrees/agent-<id>
git branch -D <branch-name>

# Nuclear: remove ALL agent worktrees (won't touch your main checkout)
for wt in .claude/worktrees/agent-*; do
  git worktree remove --force "$wt" 2>/dev/null
done
# then prune any leftover branches you don't want
git branch | grep -E "^\s+(fix|feat|ts|docs)/" | xargs -I {} git branch -D {}
```

Only do the nuclear path when no agent is running — otherwise you'll yank the floor out from under it.

## 12. The verify-agent workflow

When making protocol/transport changes, a verify-agent is spawned in an isolated worktree to:

1. Run `go build ./...`, `go vet`, `go test ./internal/...`, mobile `tsc --noEmit`, mobile `npm run build`, desktop frontend `tsc --noEmit`.
2. Walk file-transfer, remote-input, and AOA flows end-to-end byte by byte.
3. Identify real bugs (not lint noise) and ship fixes as small focused commits.
4. Return a report with what it found, what it shipped, and what it left as known follow-ups.

Example: the `fix/verify-files-remote-aoa` run produced three commits merged into `main` via merge commit `2dae2b0`:

- `c9cdf4a fix(files): live progress + 5x faster WS-chunked send`
- `07a14b2 fix(remote): accelerated mouse + USB-mode hint`
- `7de9333 fix(aoa): heartbeat + touch clamp + protocol tests`

Run it manually when you want a deep pass before tagging a release.

## 14. Verification checklist

Before reporting a build as good:

- [ ] `go build ./...` — clean
- [ ] `go test ./internal/...` — green
- [ ] `cd desktop/frontend && tsc --noEmit` — clean
- [ ] `cd mobile-cap && npx tsc --noEmit -p tsconfig.json && npm run build` — clean
- [ ] `git status --short` — only intended changes
- [ ] `git ls-files | git check-ignore --stdin` — empty (no tracked file accidentally ignored)
- [ ] Wi-Fi pair end-to-end: Discovery → pair code → Stream visible
- [ ] USB-AOA: orb reaches green, mirror visible
- [ ] File send Mac→phone: progress bar advances mid-stream (not a 0→100 jump)
- [ ] Remote drag: small deltas precise, long flings cover the screen
